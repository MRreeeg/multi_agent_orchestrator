# 调试记录

本文件记录 multi_agent_orchestrator 本地调试与功能接入过程。

## 2026-08-12 opencode serve 卡死/超时系列修复 + 浏览器窗口 + 控制台渲染

**背景**：架构师/执行者节点（opencode serve + deepseek-v4-flash-free）多次卡死：
模型陷入"探索循环"（反复 read/glob/grep 数预算、复述计划），一次 turn 拖到
HTTP 客户端 10 分钟超时才报错，整条流水线干等。

**改动（serve 模式加固）**

- `internal/executor/opencode/client.go`：
  - `Prompt` 支持 `system` 槽位（serve API 合法字段，比用户消息权威）；
  - `tools` 传参改为 `map[string]bool`（serve API 类型是 Record<toolID,boolean>
    转 permission 规则；`{"*": false}` 全禁，具名 deny 列表做只读模式；
    注意：传 `[]` 数组会 400 `Expected object | null`）；
  - `HistoryMessage` 增加 `CreatedMs`（info.time.created，毫秒），供恢复扫描锚定当前轮；
  - HTTP client 超时移除（原 5/10 分钟），deadline 全部交给调用方 ctx，
    否则 15 分钟执行者预算会被 5 分钟客户端超时架空。
- `internal/orchestrator/opencode_runtime.go`：
  - `opencodeDiscipline`：turn 预算（默认 5 分钟）+ 三段 system 纪律提示
    （默认 / 只读 / 无工具，最后一种已删——生产无调用者，属死代码）；
  - 预算到期：abort turn → `History` 捞**本轮**（按 turnStart 时间锚定）产出的
    assistant 文本当部分结果交付，零输出才算失败；
    只对 `context.DeadlineExceeded` 恢复，500/连接错误直接失败不捞历史；
  - 只读模式 deny 列表：bash/edit/write/move/patch/create/delete/task/
    webfetch/websearch/mcp__*；保留 read/grep/glob。
- `internal/orchestrator/pipeline.go`：按角色设 serve turn 预算
  （架构师 5 分钟 + ToolsReadOnly，审查者 5 分钟，执行者 15 分钟），
  三个 ExecutorOpencode 判断块合并为一个。
- `internal/executor/opencode/opencode.go`：run 模式透传 `--max-steps`。

**改动（UI）**

- 点 runtime 端口徽章 / Open 按钮 → 新增 `POST /orchestrator/api/runtime/open`
  （校验 loopback http(s)）→ 服务端 `rundll32/open/xdg-open` 打开系统默认浏览器
  独立窗口，不再走 WebView2 里 window.open 的小标签页（失败才回退）。
- Runtime Console：推理（reasoning）默认折叠为 `<details>`（点击展开，
  展开状态随轮询刷新保留）；回答/推理内容改走主聊天同一个 `renderMarkdown`
  （标题/表格/代码块/加粗/引用），不再裸显示 Markdown 源码。
- 前端超时：`apiTimeoutMs` 支持路径形状匹配 ——
  `/runs/*/analysis` 260s、`/runtimes/*/message` 300s（后端分别 4 分钟 / 10 分钟），
  修掉"分析失败: 请求超时（15秒）"类误报（前端 15s abort 会把后端子进程/响应掐断）。
- 节点配置卡片的"职责描述"改为只读预览 + 点击弹出大窗口
  （`#role-editor-modal`，可拖拽/调整大小，Ctrl+Enter 保存）。

**实测验证**

- `tools={"*": false}` 与具名 deny 列表用真实 serve + deepseek-v4-flash-free 验证：
  200 返回、模型纯文本回答；只读模式下模型能 read 文件（读了 oc_msg_req.json）
  且无法 bash/edit/write。
- 全部相关单测通过（client payload 形状、deny map、discipline 预算、serve 路由）。

**教训**

- 弱模型 + 全量工具 = 探索循环温床；"禁写禁执行、保留只读"是比纯提示词更硬的约束。
- 前端 fetch 默认 15s 超时是"伪超时"重灾区：慢接口必须显式加长，
  否则 abort 会连带取消服务端慢操作，表现为"服务好像挂了"（其实 serve/会话都还在）。
- 会话复用场景下从 History 恢复产物必须按轮次时间戳锚定，否则会把上一轮的文档
  冒充本轮结果。


## 2026-08-06 前端布局调整（左侧 dock）

- 左侧 dock 从 56px 加宽到 190px，导航按钮显示图标 + 功能名（对话 / 管道编辑器 / 执行记录）。
- 历史记录不再单独占一个页面：会话列表直接嵌入左侧 dock 底部（"历史会话"区），
  点条目即切换会话；移除原 `panel-history` 页。
- init 时加载历史列表（原来只在切到历史页时才加载）。
- 新建会话显示初始欢迎画面（清空画布 + 切回对话面板 + 显示 hero 提示）。
- 修复欢迎画面"空白"根因：`chatMessages.innerHTML = ''` 会把 `#chat-welcome` 节点
  从 DOM 摘除，之后 `style.display=''` 无效；新增 `resetChatToWelcome()`
  （只移除消息气泡、保留并显示欢迎节点），替换三处清空点。
- 用 Playwright 真实浏览器验证：侧边栏 190px + 三个功能名、历史 6 条嵌入侧边栏、
  新建会话后欢迎画面可见（heroVisible=true）。
- 欢迎页精简：副标题缩短为一行；输入框示例缩短为 24 字符；
  "新建会话"按钮移到顶部栏；欢迎页显示时隐藏底部输入栏（display:none），
  有消息后输入栏才出现（浏览器实测通过）。
- 聊天气泡 Markdown 渲染：新增 renderMarkdown()（标题/加粗/列表/代码块/行内代码/链接/换行），
  用于 addChatMessage、历史消息、流式输出。
- 会话切换不再弹 confirm：switchOrchestrationSession / resumeSession 直接保存后跳转。
- 运行看板（Loop 运行看板）从聊天区顶部移到右侧配置面板；执行时自动展开右侧面板。
- 新建会话按钮从顶部栏移到左侧 dock"历史会话"上方。
- 浏览器实测：Markdown 渲染生效；欢迎区中心=主区中心（排除左侧 dock）；
  切换会话 0 弹窗；看板在右侧且可见；新建按钮在侧边栏；欢迎页底部输入栏隐藏。
- 修复欢迎区居中偏差：隐藏的右侧配置面板仍占用 300px 栅格列，导致主区被挤窄、
  欢迎区偏左；配置面板隐藏时应用 `app--no-config` 让该列坍缩为 0。
  实测欢迎区中心从 665 → 815（= 可见主区中心，右移 150px）。
- 聊天排版：气泡加宽（AI 90% / 用户 78% 右侧对齐，max 1080px）、字体 13.5→14.5px，
  充分利用主区宽度但保留左右区分；Markdown 渲染补充表格（pipe table）与
  引用块（> ）支持及对应样式（Obsidian 风格）。
- 历史记录排序：当前打开的会话固定置顶，其余按时间倒序。
- 动效：页面切换（panel fade+slide）、弹窗（overlay 淡入 + modal 上浮缩放）、
  运行看板出现均有过渡动画。
- pipeline 布局：生成/加载/预设流水线自动居中到画布中间（applyAutoLayout /
  centerPipelineGraph），不再从左上角开始排列。
- 浏览器实测：AI 气泡宽 1080px、用户气泡 944px 右对齐；表格/引用渲染生效；
  历史首个卡片为当前会话；3 节点流水线居中（x=105/355/605，中心 450）。

## 2026-08-06 opencode 执行器接入

**改动**

- 新增 `internal/executor/opencode` 包：
  - run 模式：`opencode run -m <provider/model> --format json`，解析 JSON 事件流；
  - serve 模式：HTTP 客户端封装 opencode server API
    （POST /session、POST /session/{id}/message、abort、message 历史）。
- 新增 `internal/orchestrator/opencode_runtime.go`：保留运行时管理
  （spawn `opencode serve`、状态机、Runtime Console、interrupt/stop）。
- pipeline 注册：`ExecutorOpencode` 常量、校验（run/serve、provider/model 格式）、
  模型原样透传、前端 nodeTypes 与 runtime 路由。
- DeepSeek 官方 API：key 取自 `D:\code\appii\deepseek.txt`，写入 `.env`
  （gitignored，不入库）；`reasonix.toml` 增加 `deepseek-official` provider。
- 修复：新建会话后前端显示空白（清空画布并切回对话欢迎页）。
- 修复：全局 `/runtimes` 路由被会话级路由抢先匹配（补 `/orch-sessions/` 前缀判断）。
- 修复：opencode 运行时漏接 `SetUpdateSink`（前端收不到运行时事件，控制台按钮不出现）。
- 补充：opencode serve 控制台实时事件流 —— 订阅 `GET /event`（SSE），
  解析 `message.part.delta`（增量文本）与 `message.part.updated`（完整文本+类型），
  实时喂入 Runtime Console（推理/回答分块显示）。原实现只做阻塞式 HTTP 请求，
  控制台看不到过程；方案文档当时只写了"轮询 + SSE 唤醒"，未细化 opencode 侧的事件订阅。

**实测验证**

- opencode 免费模型 `opencode/deepseek-v4-flash-free`：run 模式端到端跑通（写文件成功）。
- opencode serve 模式：HTTP 保留运行时跑通（写文件成功），Runtime Console 可读
  （sessionID / 事件 / 输出）。曾遇到 message 接口要求 model 为
  `{providerID, modelID}` 对象，已修正并加单测。
- DeepSeek 官方 `deepseek/deepseek-v4-flash`（opencode）与
  `deepseek-official`（reasonix）各一次真实调用成功。
- 全程子进程带 `CREATE_NO_WINDOW`，无黑框。
